## 只读采样与适用边界

在既有 5 秒诊断周期增加 CPU 型号/逻辑核数、当前 cgroup v2 及祖先的配额、节流计数和有效 CPU 数，并按自身后代进程的固定角色估算 Node、Chromium 与其他进程的 CPU tick、存储 IO 和 RSS。保留 PID/starttime 身份校验、父链变化与退出丢失计数；只计算持续存活且身份匹配的进程差量。未知、不可读或超出预算时明确返回不可用，不以零代替。

进程命令行、环境变量、任意进程名、执行文件路径、cgroup 路径和错误正文都不输出。执行文件链接仅在内存中提取已知 basename，用于处理 Node 的 MainThread 名称；不运行子命令或更改系统设置。扫描采用线性父子关系遍历，并设进程数上限与 25 毫秒协作式预算；单次内核读取无法被该预算强行中断，所以另记录实际开销。

Node 后代可能包含静态服务器，不能全部等同于 Playwright worker；RSS 总和可能重复计算共享页；存活进程差量不是完整进程树累计 CPU，短命进程可能漏采；祖先 cgroup 包含后代，计数不可相加。采样填补归因证据，不自行证明性能根因。
