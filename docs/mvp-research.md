# AI 发展史时间线：MVP 调研与待确认方案

调研日期：2026-09-29。状态：初始调研存档，已基于补充方案实施首版，见项目 README。

补充：用户新增 Agent 方法、Agent 产品和模型版本维度。最新建议见 [多维时间线方案](./multidimensional-plan.md)；本文的单一时间线与 40–60 条规模建议作为初稿保留，以新方案为准。

## 1. 已确认的需求与范围

- 第一版主题是全球 AI 发展史，面向普通读者，涵盖关键突破与代表产品。
- 用户按时间探索，在节点中了解事件，并跳转到相关原始资料。
- 先调研、确认方案，再实施。网站展示语言尚未确定；内容范围不受语言或国家限制。
- 当前工作目录为空，没有需要沿用的技术栈。

建议定位：一部可探索、可追溯来源的 AI 简史。完整覆盖主要历史阶段，以精选事件讲清演进，不承诺穷尽全部事件。

## 2. 参考产品与资料

本轮比较依据公开页面、内容结构和官方文档，未进行完整的交互可用性测试。

| 参考 | 已观察到的做法 | 对本项目的启发 |
| --- | --- | --- |
| [Computer History Museum：AI & Robotics](https://www.computerhistory.org/timeline/ai-robotics/) | 按年份组织事件，结合图片和说明，覆盖 AI 与机器人 | 用时间和故事帮助大众进入主题；事件仍需回查原始材料 |
| [Our World in Data：AI 简史](https://ourworldindata.org/brief-history-of-ai) | 通过历史叙事、代表系统和能力变化解释发展 | 每个事件应解释“为什么值得关注”，避免只列名称 |

| [Knight Lab TimelineJS](https://github.com/NUKnightLab/TimelineJS3) | 提供开源故事型时间线；官方文档支持结构化 JSON | 适合快速验证横向叙事；定制列表、筛选和独立事件页仍需额外工作 |

差异化建议是：完整历史跨度、通俗说明、明确来源、可分享的事件页面。不是依靠收录数量建立价值。

## 3. 内容组织建议

首版建议 40–60 个事件，其中约 20 个标为主线里程碑。默认读主线，可切换查看全部精选事件。这里的数量是产品建议，尚未完成全量选题或逐条核验。

建议从 1943 年起，到首版明确标注的内容截止日。更早的计算理论可以放入序章或背景资料。上线前补核 2025–2026 年的候选事件；本次样例不代表已覆盖到今天。

为了导航，可暂分六个章节。以下是编辑分组，不是公认且互斥的学术分期，各技术路线会跨越章节：

| 时间范围 | 章节主题 | 应覆盖的方向 |
| --- | --- | --- |
| 1943–1956 | 思想与学科起点 | 人工神经元、图灵、达特茅斯研究项目 |
| 1957–1979 | 早期探索与限制 | 符号推理、感知机、语言交互、专家系统、机器人、早期挫折 |
| 1980–1999 | 商业化与学习方法 | 专家系统兴衰、神经网络、统计学习、强化学习、深蓝 |
| 2000–2011 | 数据与计算条件 | 数据集、计算资源、语音、自动驾驶、机器学习应用 |
| 2012–2021 | 深度学习突破 | 视觉、生成模型、AlphaGo、Transformer、科学应用 |
| 2022–内容截止日 | 生成式 AI 普及 | 对话产品、开放模型、多模态、推理、智能体及实际能力边界 |

选题规则：能够代表方法突破、能力变化、广泛应用，或解释发展的重要转折；每条必须有可核查依据。不按国家分配名额，也不只追踪少数厂商。近年一般版本更新不自动成为里程碑。

完整内容清单仍需补齐专家系统、AI 寒冬、统计学习、数据集、机器人、科学应用等方向。寒冬等持续过程应以区间或背景说明表达，不能编造一个精确发生日。涉及“第一”“首次发明”的表述要特别核对。

## 4. 已核查的代表事件样例

这些条目用于验证日期与来源结构；不是最终 40–60 条清单。“为何入选”属于本项目的编辑判断。

| 日期 | 事件 | 为何入选 | 来源及类型 |
| --- | --- | --- | --- |
| 1943-12 | McCulloch 与 Pitts 发表神经活动逻辑模型论文 | 展示人工神经网络的早期思想 | [论文出版页](https://doi.org/10.1007/BF02478259)，原始论文 |
| 1950-10 | 图灵发表《Computing Machinery and Intelligence》 | 从“机器能否思考”引入读者 | [Mind 原论文](https://academic.oup.com/mind/article/LIX/236/433/986238)，原始论文 |
| 1956 年夏 | 达特茅斯 AI 夏季研究项目 | 展示学科形成的标志性活动 | [1955 年提案](https://www-formal.stanford.edu/jmc/history/dartmouth/dartmouth.html)，原始文件；[Dartmouth 回顾](https://ai.dartmouth.edu/our-story)，机构回顾 |
| 1986-10-09 | Rumelhart、Hinton、Williams 发表反向传播相关论文 | 解释神经网络怎样调整内部连接 | [Nature 论文](https://www.nature.com/articles/323533a0)，原始论文；不写成反向传播在此首次被发明 |
| 1997-05 | 深蓝在系列赛中战胜卡斯帕罗夫 | 大众容易理解的机器能力里程碑 | [IBM 历史记录](https://www.ibm.com/history/deep-blue)，参与机构回顾 |
| 2012 | AlexNet 相关论文发表 | 介绍深度神经网络在图像识别中的突破 | [NeurIPS 论文](https://papers.nips.cc/paper_files/paper/2012/hash/c399862d3b9d6b76c8436e924a68c45b-Abstract.html)，原始论文 |
| 2016-03 | AlphaGo 以 4:1 战胜李世石 | 介绍学习方法与搜索的结合 | [DeepMind 项目页](https://deepmind.google/research/alphago/)，官方项目回顾 |
| 2017-06-12 | 《Attention Is All You Need》首次提交 arXiv | 引入 Transformer 这一重要架构 | [arXiv 原论文及版本记录](https://arxiv.org/abs/1706.03762)，原始论文 |
| 2022-11-30 | ChatGPT 公开研究预览发布 | 代表面向大众的对话式生成 AI 产品 | [发布公告](https://openai.com/index/chatgpt/)，原始公告 |
| 2025-01-20 | DeepSeek-R1 发布 | 介绍公开模型与推理方向的代表案例 | [发布公告](https://api-docs.deepseek.com/news/news250120/)，原始公告 |

实测发现的日期问题：[CHM 年表](https://www.computerhistory.org/timeline/ai-robotics/) 将图灵测试放在 1951 年分组，而 [Mind 原论文](https://academic.oup.com/mind/article/LIX/236/433/986238) 是 1950 年。节点若定义为“论文发表”，应使用论文的出版日期。不能把不同年表的日期直接拼起来。

同样，达特茅斯提案写于 1955 年，研究项目发生在 1956 年；事件时间与来源发布时间需要分别保存。Transformer 的预印本提交日也不等于会议发表日。

## 5. MVP 用户体验

建议采用纵向时间线作为主视图，桌面侧边固定年代导航，手机顶部提供年代选择。每个日期节点下可以容纳多个事件卡片，同年事件不必合并成一篇长文。

阅读流程：进入 AI 时间线 → 选择主线或全部事件 → 按年代浏览或搜索 → 展开事件 → 打开原论文、公告或档案 → 返回原阅读位置。

| 方案 | 优点 | 代价 | 建议 |
| --- | --- | --- | --- |
| 纵向时间线＋年代导航 | 阅读自然，长说明与手机适配容易 | 时间跨度的空间感较弱 | MVP 首选 |
| 横向可缩放时间轴 | 适合比较事件时间关系，探索感强 | 长历史的密度差异、触屏操作和标签重叠更难处理 | 后续验证 |
| 全屏逐页故事 | 适合约 20 个精选节点的引导阅读 | 浏览全部事件、快速跳转与筛选较弱 | 可作为后续导览模式 |

纵向视图按时间排序，但节点间距不代表真实时间长度，界面应明确这一点。大跨度空白用年代标题或间隔提示表达。不要通过拉长页面来表示几十年的跨度。

每张事件卡片只展示：日期、标题、一句话说明、类别。展开后展示：发生了什么、为什么重要、当时的局限、相关人物或组织，以及 1–3 条来源。

来源按钮展示资料名、发布方、类型和语言，例如“原论文 · arXiv · English”，而不是统一写“了解更多”。官方回顾与当时的原始资料分开标识；原始资料缺失时如实说明。

独立事件页用于分享、搜索引擎收录和直接访问。时间线内可用内联展开减少跳转，详情页复用相同内容。外部资料用普通链接直达，保留时间线阅读位置。

## 6. 功能边界与验收

第一版包括：

- 主线／全部精选事件切换。
- 年代跳转、关键词搜索、少量类别筛选。
- 事件说明、来源链接、独立事件页。
- 手机和桌面布局；键盘可操作的展开与导航。
- 编辑说明：收录原则、内容截止日、最近更新日。

暂缓账户、评论、收藏同步、在线编辑后台、AI 问答、自动抓取发布、复杂关系图、横向缩放时间轴。多主题仅在数据和路由中保留扩展位置。

验收重点：

1. 约 20 个主线节点能串起完整历史阶段，展开到全部后仍能定位和阅读。
2. 每个已发布事件至少有一条经核查的来源；原始资料与回顾资料标签准确。
3. 年、月、日和区间日期正确显示，不将未知日期补为 1 月 1 日。
4. 搜索无结果、多个事件同日、详情直达、刷新、返回、移动端阅读均有合理行为。
5. 事件页可以独立访问；筛选状态可记录在 URL 中，清除筛选容易发现。
6. 上线前逐条核查史料和来源链接；技术构建、链接检测、内容审校分别通过。

可用一次小规模读者验证观察：能否找到一个指定事件、讲出某个突破的重要性、打开对应原始材料。这比首版追求大量复杂功能更贴近需求。

## 7. 技术方案比较

下表是根据当前功能边界作出的工程判断，尚未压测或实施。

| 方案 | 适合场景 | 本项目取舍 |
| --- | --- | --- |
| Astro＋TypeScript＋本地结构化内容 | 内容阅读、静态事件页，局部搜索筛选 | 当前首选，先使用少量浏览器脚本实现交互 |
| Next.js＋TypeScript＋本地结构化内容 | 团队熟悉 React，后续明确有账户或后台 | 可选；当前需求用静态导出即可 |
| TimelineJS 嵌入 | 很快完成一个故事型时间线 | 可做验证原型；正式产品需要自定义的筛选、详情和移动布局，建议自己实现简单纵向组件 |

[Astro Content Collections](https://docs.astro.build/en/guides/content-collections/) 支持从本地 Markdown、JSON 等内容生成页面并定义 schema。[Next.js 静态导出](https://nextjs.org/docs/app/guides/static-exports) 也能生成每路由 HTML，但依赖服务器的动态功能不在静态导出范围内。

首版建议每个事件一份 Markdown 文件，元数据放在 frontmatter，正文写解释性内容。读取时进行结构校验；无需数据库、运行时 AI 接口或专用搜索服务。40–60 条事件可在浏览器筛选标题、摘要、人物与标签。

建议路由：`/ai/` 为时间线，`/ai/events/<slug>/` 为事件页。若确认做双语，再确定语言前缀和缺失翻译处理规则；不应把中文文本与事件唯一标识绑定。

部署选择普通静态托管即可。正式实施时再根据既有账号、域名和主要访问地区确认平台，当前不采购服务、不部署。

## 8. 数据模型与内容维护

每条事件建议包含：

| 字段 | 用途 |
| --- | --- |
| id、slug、topicId | 稳定标识、独立 URL、未来其他主题 |
| title、summary、body、locale | 显示内容与语言 |
| startDate、endDate、datePrecision、dateLabel | 年/月/日、区间和“1956 年夏”等非精确日期 |
| dateBasis | 说明节点是论文发表、研究活动、产品发布还是正式开放 |
| category、tags、entities | 类别、标签、人物与组织 |
| isMilestone | 决定是否进入快速阅读主线 |
| sources | 资料名、URL、发布方、资料类型、语言、发布时间、核查日期 |
| editorialStatus、updatedAt | 草稿／已核查／已发布及更新时间 |

不要把历史日期直接当作含时区的时间戳；保留原有精度。排序所需的内部键与用户看到的日期分开。事件相同时按稳定规则排序。

维护流程：发现候选 → 确定事件边界与日期 → 找原始材料 → 撰写通俗说明 → 核查 → 发布。AI 可以辅助查找和草拟，发布前核对来源是否真正支撑描述。

链接应指向具体文章、论文或公告，避免只有机构首页。保留 DOI 和原始 URL；来源迁移或失效时可增加替代来源，保留出处记录。链接检测遇到登录、访问限制或反爬时需人工区分，不能一律认定死链。

对重要性或因果关系的判断应与史实区分。厂商公告适合证明发布事实，不能单独证明“行业最好”或“具有通用智能”等评价。

## 9. 建议的实施顺序与待确认项

确认后再进入实施，顺序建议为：

1. 确认展示语言、纵向主视图和内容量。
2. 整理约 20 条主线及 40–60 条候选清单，补齐当前样例遗漏的历史阶段。
3. 用少量已核查事件验证桌面与手机页面，包括同年多事件和不精确日期。
4. 完成筛选、搜索、详情页及剩余内容。
5. 做内容审校、链接核查和必要功能验证，再发布首版。

内容核验是主要工作量来源。近年事件过密、历史日期口径差异和后续更新责任，是比组件选择更需要提前解决的问题。

建议待确认方案：面向大众的全球 AI 发展史；纵向分年代；40–60 个精选事件、约 20 个主线里程碑；原始资料优先；Astro 静态站点。网站使用中文、英文还是双语仍需用户确定，全球内容范围与展示语言是两项独立选择。
