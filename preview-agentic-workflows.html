GitHub Agentic Workflows 正式可用：把代理任务接入 Actions

GitHub将自然语言描述的仓库任务编译为Actions工作流，用于议题分流、故障分析和文档维护；这是工作流工具，不是新模型。

为什么重要

编辑解读：代理任务进入既有CI治理体系，配置、权限和输出审查成为与模型能力同样重要的交付条件。

编辑概述；具体事实见下文及其来源。

经过：从预览到正式可用

10月28日公告确认Agentic Workflows正式可用。Markdown任务描述转为标准Actions YAML，复用运行器与组织策略；Copilot只是可选执行引擎之一。这里记录产品阶段变化，不把它和同日Fusion模型路由发布合并。1原文定位：开头；Additional capabilities；Get started

权限：默认只读不等于没有写入

公告描述默认只读执行、沙箱和防火墙，并由safe outputs校验输出、专门任务扫描拟议变更。这些是厂商设计说明，而非独立安全认证；允许的后续输出仍可能改变仓库。1原文定位：Built-in safeguards

使用条件：先审配置，再看运行结果

官方入门示例生成仓库状态报告，要求仓库写权限、启用Actions和所选AI引擎的账号配置；向导可加入工作流并触发执行。文档提醒先检查数据处理、仓库敏感性及日志访问，运行成功后仍需查看生成的议题和日志。2原文定位：Prerequisites；Step 2；Step 3

编辑分析：自动完成不是自动批准 · 编辑解读

可先用只读分析、小范围输出和明确预算验证价值，再扩大任务范围。把“流程运行结束”“建议正确”“变更可合入”作为三个不同验收点，避免用一次成功运行替代测试与维护者判断。

阅读这段历史时

Free、Team和Enterprise可使用产品，但默认Copilot CLI引擎仍需Copilot许可；正式可用不等于免费推理或无需人工验收。本次未安装工具、运行工作流或复测安全性。
